# Feature Specification: завантаження й розбір документів PSI

**Feature branch:** `001-psi-ingest`
**Створено:** 2026-11-14
**Статус:** Draft → In implementation
**Вхід:** «Запарсити всі дослідження з теми combustion з PSI. На виході — готові JSON.
Завантажувати тільки pdf, docx, csv, xlsx. Обробку тексту й таблиць писати окремо.
Скрипт має бути адаптивним на майбутнє й відповідати контракту та правилам репозиторію.»

## User Scenarios & Testing

### User Story 0 — Файли контракту однією командою (P1, головне)

Користувач запускає `python3 -m pipeline` і отримує в `data/processed` чотири файли за контрактом
(`contracts/README.md`): `tests.json`, `investigations.json`, `scenarios.json`, `meta.json`.
Сайт читає їх без змін.

**Незалежна перевірка:** `python3 contracts/validate.py data/processed` → `OK`.

**Acceptance:**
1. **Given** завантажені таблиці, **Then** кожен рядок кожної таблиці експериментів стає `TestRecord`
   або пропускається з причиною (виноска, відеодані), яку видно в журналі й у `meta.dataNotes`.
2. **Given** 7 рядків з `data/fixtures/tests.json`, **Then** рушій відтворює їх зведені поля точно.
3. **Given** клітинку, яку не можна прочитати впевнено (`037 mm`, `-0.28` см/с), **Then** поле `null`,
   причина в `notes`, вихідне значення в `raw`.
4. **Given** метадані 24 досліджень, **Then** кожна картка має `summary` з дослівною цитатою, перевіреною кодом.


### User Story 1 — Повний знімок досліджень з горіння (P1)

Користувач запускає одну команду і отримує на диску метадані всіх
досліджень Combustion Science з PSI і всі потрібні документи вибраних форматів.

**Чому P1:** без цього немає даних ні для маппінгу таблиць, ні для карток досліджень.

**Незалежна перевірка:** `python3 -m pipeline` на чистому клоні → у `data/raw/` 24 папки
`PSI-*` з `metadata.json`, `files.json` і файлами; повторний запуск нічого не качає.

**Acceptance:**
1. **Given** порожній `data/raw`, **When** запускаємо ingest, **Then** для кожного дослідження з
   `Research Area = Combustion Science` з'являються `metadata.json` (відповідь API без змін) і
   `files.json` (повний перелік файлів з рішенням «взяти / пропустити й чому»).
2. **Given** файл з папки `Raw Data` або з розширенням поза списком, **Then** він не завантажується,
   а в `files.json` записано причину.
3. **Given** файл уже на диску з тим самим розміром, **When** повторний запуск, **Then** мережевого
   запиту за ним немає.
4. **Given** дослідження з порожнім `added[]` (PSI-99, PSI-69, PSI-68, PSI-22), **Then** перелік
   файлів однаково повний: він береться з дерева файлів сайту (`POST /files/v2`).

### User Story 2 — Документи як JSON (P1)

Користувач отримує кожен завантажений документ як JSON з текстом і таблицями в порядку документа,
з посиланням на місце в джерелі (сторінка, абзац, аркуш, рядок).

**Незалежна перевірка:** `python3 -m pipeline.extract` → `data/extracted/PSI-*/<файл>.json`
і `data/extracted/index.json`; усі файли проходять перевірку схемою.

**Acceptance:**
1. **Given** CSV з BOM, **Then** назва першої колонки без BOM, клітинки дослівно як рядки, `sourceRow`
   = номер рядка даних (1 = перший рядок після заголовка).
2. **Given** XLSX з кількома аркушами, **Then** кожен аркуш — окрема таблиця з назвою аркуша.
3. **Given** DOCX з абзацами й таблицями, **Then** блоки йдуть у порядку документа, заголовки мають рівень.
4. **Given** PDF, **Then** текст розбито по сторінках; знайдені таблиці позначені `confidence: low`.
5. **Given** документ, який не вдалося розібрати, **Then** JSON однаково створено зі `status: failed`
   і текстом помилки; решта документів обробляється.

### User Story 3 — Розширення без переписування (P2)

Розробник додає новий формат (наприклад `pptx` або `doc`) або нове джерело, не змінюючи наявних
обробників: пише один клас і реєструє його.

**Незалежна перевірка:** новий обробник підхоплюється реєстром; зміна списку форматів чи запиту —
лише в `pipeline/config/ingest.json` або прапорцем CLI.

### Edge Cases

- Тимчасове посилання S3 спливає → посилання отримуємо безпосередньо перед кожним завантаженням.
- Мережа падає посеред файла → пишемо в `*.part`, перейменовуємо лише після успіху; повтор з паузою.
- Файл більший за ліміт (за замовчуванням 60 МБ) → пропуск із причиною `too-large`.
- Однакові заголовки колонок / порожній заголовок → ключі розрізняються суфіксом, попередження.
- PDF без текстового шару (скан) → `status: partial`, попередження `no-text-layer`.
- Пошук повертає дослідження інших напрямів (`combustion` знаходить 26, з них 24 Combustion Science)
  → фільтр за `Research Area` з конфігу.
- CSV не в UTF-8 → запасні кодування з попередженням.

## Requirements

### Functional

- **FR-001** Відкриття досліджень: пошук PSI за запитом з конфігу (`combustion`) + фільтр за `Research Area`;
  можна обмежити списком id (`--ids PSI-25 PSI-99`).
- **FR-002** Для кожного дослідження зберегти відповідь `repo/investigations/<id>` дослівно в `metadata.json`.
- **FR-003** Перелік файлів = об'єднання дерева `files/v2`, `experimentalTable[]` і `added[]` без дублів.
- **FR-004** Відбір файлів: дозволені розширення (за замовчуванням `pdf, docx, csv, xlsx`), виключені папки
  (за замовчуванням `Raw Data`), ліміт розміру. Кожне рішення записане з причиною.
- **FR-005** Завантаження: послідовно, з паузою, з повтором, атомарний запис, кеш за розміром файла.
- **FR-006** Кожен формат має окремий обробник; обробники повертають спільну модель блоків
  `text` і `table`.
- **FR-007** Вихід розбору: один JSON на документ + `index.json` з переліком досліджень і документів.
- **FR-008** Таблиці зберігають клітинки дослівно як рядки (`raw`) і номер рядка джерела.
- **FR-009** Вихідні JSON перевіряються схемами з `pipeline/schema/` тим самим валідатором, що й контракт.
- **FR-010** Метадані в `index.json` подаються в полях, названих як у `Investigation` контракту
  (`id`, `acronym`, `title`, `doi`, `url`, `kind`, `yearStart`, `yearEnd`, `publications`), щоб картки
  лише доповнювали їх.
- **FR-012** `tests.json`: JSON-маппінг на кожну таблицю (`pipeline/mappings/`) + детермінований рушій
  (`pipeline/normalize/`); одиниці контракту (%, кПа, см/с, мм, с, мм/с); `raw` дослівно; `inferred`
  для полів не з колонки; `confidence` знижується за неоднозначності.
- **FR-013** `investigations.json`: метадані PSI + поля, пораховані з `tests.json`; твердження — дослівні
  речення текстів PSI з перевіркою цитати кодом; напрями безпеки й обладнання з `pipeline/config/contract.json`.
- **FR-014** `scenarios.json` з `pipeline/config/scenarios.json`; `meta.json` з версією контракту з `contracts/types.ts`.
- **FR-015** Збірка завершується `contracts/validate.py data/processed`; невідповідність = помилка запуску.
- **FR-011** Одна команда `python3 -m pipeline` проходить усі етапи; етапи можна запускати й окремо (`ingest`, `extract`); `--dry-run` показує план без завантажень.

### Non-functional

- **NFR-001** Без бази даних і серверів (AGENTS.md §2.9). Залежності: `requests`, `openpyxl`,
  `python-docx`, `pdfplumber`.
- **NFR-002** Python 3.9+ (цільовий 3.11+, як у стеку).
- **NFR-003** Не змінює `contracts/` і `data/processed/`.
- **NFR-004** Бінарні документи не комітяться (`.gitignore` уже це робить); CSV і JSON — комітяться.

### Key Entities

- **InvestigationRef** — id, акронім, назва, research area, версія.
- **RemoteFile** — шлях S3, назва, папка, розмір, версія, рішення відбору й причина.
- **ExtractedDocument** — джерело, формат, обробник, статус, попередження, `blocks[]`.
- **Block** — `text` (вид, текст, місце) або `table` (назва, колонки, рядки з `sourceRow` і `raw`, місце).

## Success Criteria

- **SC-001** 24 дослідження Combustion Science мають `metadata.json` і `files.json`.
- **SC-002** Таблиці експериментів (22 CSV) розібрано; 2 009 непорожніх рядків даних. (2 870 у `docs/03-data-sources.md` — фізичні рядки: у `CFI-G_Inverse Flames.csv` 861 з 1 015 рядків повністю порожні.)
- **SC-003** Усі вихідні JSON проходять перевірку схемою.
- **SC-004** Повторний запуск ingest не робить жодного завантаження файла.
- **SC-005** Новий формат додається одним файлом-обробником і рядком у конфігу.
- **SC-006** `python3 contracts/validate.py data/processed` → OK (1 989 записів, 24 картки, 5 сценаріїв, 22 таблиці).
- **SC-007** Нова таблиця додається одним JSON-маппінгом; збірка попереджає про таблиці без маппінгу.

## Out of Scope

- Тексти карток від LLM (зараз — лише дослівні речення PSI за фіксованими правилами).
- Ручна вибірка для `meta.quality`.
- Конвертація `.doc`, `.ppt`, `.pptx` (можна додати обробником пізніше).
- Папки `Raw Data`, відео, архіви `.zip`.
