# AGENTS.md — спільний контекст для всіх AI-агентів і людей

> Кожен агент читає цей файл на початку кожної сесії (`CLAUDE.md` його імпортує).
> Після нього агент читає файл свого напряму з `tracks/` і `docs/04-contracts.md`.
> Змінювати цей файл можна лише рішенням команди, записаним у `docs/decisions.md`.

## 1. Що ми будуємо

**Flame Atlas** (робоча назва) — веб-дашборд для челенджу NASA Space Apps 2026
«Flame in Freefall: SI-Powered Fire Safety Insights from Microgravity Combustion Data».

Дашборд підсумовує, ранжує й тлумачить 24 дослідження з горіння з бази NASA PSI
(psi.nasa.gov) для пожежної безпеки кораблів, станцій, місячних і марсіанських баз,
герметичних роверів. Користувач:

1. задає середовище (кисень, тиск, гравітація, потік повітря, матеріали) і отримує
   ранжований список найрелевантніших досліджень і тестів з поясненням;
2. фільтрує й експортує єдину таблицю тестів (дані для прогнозного моделювання);
3. бачить, які дослідження стосуються запобігання, виявлення й гасіння пожеж,
   порівнює їх і бачить прогалини в даних;
4. бачить для кожного дослідження картку з джерелами і те, що змінювалось між тестами.

Аудиторія: професори, аспіранти, студенти, аерокосмічні інженери. Вони пробачать
простий інтерфейс, але не пробачать неправильне число.

Дедлайн подання: **неділя 15 листопада 2026, 23:59 за київським часом**.

## 2. Незмінні принципи

1. **Жодного твердження без джерела.** Кожен факт у картці, поясненні чи відповіді
   має `citations` з документом і місцем у ньому. Немає джерела — немає твердження.
2. **`null` краще за здогад.** Якщо значення не знайдено в джерелі, поле лишається `null`.
   Модель нічого не дофантазовує з «загальних знань про горіння».
3. **AI пише маппінг, код його застосовує.** Нормалізація таблиць — це специфікація
   маппінгу на таблицю (JSON) плюс детермінований код. AI не переписує рядки по одному.
4. **`raw` зберігається завжди.** Кожен нормалізований запис містить вихідні колонки без змін
   і номер рядка у вихідному файлі.
5. **Цитати перевіряються програмно.** Дослівна цитата з тексту, який написав AI, має знайтися
   в тексті джерела. Не знайшлась — твердження відкидається.
6. **Ранжування детерміноване й пояснюване.** Бал рахує чиста функція з відкритими вагами.
   AI лише формулює пояснення, але не виставляє бал.
7. **Контракт — єдине джерело правди.** Формат чотирьох файлів даних описаний у `contracts/`
   (схеми, типи, перевірка). Змінювати його може лише власник контрактів після повідомлення в чат команди.
   Дані в `data/processed` комітимо тільки після `python3 contracts/validate.py data/processed`.
8. **Статичний сайт, LLM поки лише в підготовці даних.** Застосунок працює на готових JSON з `data/processed`,
   усе рахує в браузері й не має серверної частини. Живий виклик LLM на сайті — окремий пізніший крок.
9. **Мінімум інфраструктури.** Без бази даних, авторизації, черг і мікросервісів.
10. **`main` завжди збирається.** Перед пушем: перевірка даних і збірка сайту (розділ 5).
11. **Продукт англійською.** Інтерфейс, тексти, код, коментарі, коміти, README,
    слайди й текст подання — англійською. Внутрішні документи команди — українською.
12. **Сирі дані PSI не чіпаємо.** Папки `Raw Data` (відео, кадри, архіви, до 2 ТБ
    на дослідження) не завантажуємо. Беремо метадані й таблиці експериментів.
    Виняток: малі файли телеметрії датчиків за списком у `pipeline/config/telemetry.json`
    (рішення в `docs/decisions.md`); у репозиторій іде лише їх зведення в `data/derived/`.

## 3. Стек (рішення в `docs/decisions.md`)

- **Пайплайн даних:** Python 3.11+, pandas. Запускається локально, результат — JSON у `data/processed`.
- **Сайт:** Next.js зі статичним експортом (`output: 'export'`), TypeScript, Tailwind, shadcn/ui, Recharts.
  Серверної частини й бази немає. Хостинг: GitHub Pages з цього ж репозиторію.
- **Контракт:** JSON-схеми в `contracts/schema`, типи в `contracts/types.ts`, перевірка `contracts/validate.py`
  (чистий Python, без залежностей).
- **AI:** LLM працює тільки під час підготовки даних: пропонує маппінги таблиць, розбирає назви матеріалів,
  пише тексти карток. Кожен результат перевіряє код і людина. Подробиці: `docs/02-architecture.md`, розділ 2.

## 4. Структура репозиторію та власники

Команди «Дані й AI» і «Продукт» мають свої папки (див. `docs/09-groups-and-blockers.md`).
Папками своєї команди люди користуються спільно. У папках іншої команди агент нічого не змінює:
він пише в чат або відкриває окремий PR.

| Шлях | Команда | Що там |
|---|---|---|
| `contracts/` | Дані й AI (власник контрактів) | схеми, типи, перевірка формату даних |
| `pipeline/` | Дані й AI | завантаження з PSI, зведення таблиць, картки, збірка файлів |
| `data/raw/`, `data/processed/`, `data/fixtures/` | Дані й AI | вихідні таблиці, файли для сайту, зразки |
| `data/review/`, `submission/`, `docs/07-glossary.md` | Дані й AI | ручна перевірка, знахідка, подання |
| `apps/web/` | Продукт | сайт: сторінки, компоненти, логіка ранжування й покриття |
| CI, деплой | Продукт (власник `main` і деплою) | GitHub Actions, GitHub Pages |

## 5. Команди

```
python3 contracts/validate.py data/fixtures     # перевірка зразків (працює вже зараз)
python3 contracts/validate.py data/processed    # перевірка справжніх даних перед комітом
python3 -m pipeline.build                       # зібрати data/processed (створює команда «Дані й AI»)
cd apps/web && npm run dev                      # сайт локально (створює команда «Продукт»)
cd apps/web && npm run build                    # статична збірка
```

## 6. Правила роботи агента

- Спершу прочитай: цей файл, файл свого напряму в `tracks/`, `contracts/README.md`. Для задач з даними
  ще `docs/03-data-sources.md`, для термінів `docs/07-glossary.md`.
- Задача довша за 30 хвилин починається з короткого плану (режим планування). Менші роби одразу.
- Одна задача — одна гілка `<команда>/<номер-задачі>` (наприклад `product/pr-3-rank`), живе до 2 годин,
  зливається в `main` малими комітами. Повідомлення комітів англійською.
- Сайт будуй на зразках з `data/fixtures`, доки немає справжніх даних. Назви файлів і формат однакові.
- Результат роботи LLM (маппінг, словник матеріалів, тексти карток) зберігай у репозиторії як файл,
  щоб його могла перевірити інша людина.
- Потрібна зміна контракту — не міняй сам. Опиши зміну одним абзацом для чату команди.
- Рядок таблиці не завжди є тестом: дивись поле `granularity` і рахуй тести лише за рядками `test`.
- Не додавай залежностей без потреби. Велика нова залежність — рішення в `docs/decisions.md`.
- Кожне рішення, яке впливає на інших, запиши одним рядком у `docs/decisions.md`.
- Коротко запиши в `docs/si-usage-log.md`, що зроблено з допомогою AI: це обов'язкове поле подання.
- Усі зовнішні джерела (код, бібліотеки, дані, зображення) додавай у `submission/references.md`.
- Застряг більше ніж на 20 хвилин — зупинись і сформулюй питання для чату команди.

## 7. Доменний мінімум

- У невагомості немає плавучості, гарячі гази не піднімаються. Полум'я живе на дифузії
  кисню й потоці вентиляції, тому слабкий потік може підтримувати горіння, а не гасити.
- Три напрями пожежної безпеки: **prevention** (що й за яких умов горить),
  **detection** (дим, датчики), **suppression** (гасіння, межі згасання).
  Четвертий тег **fundamentals** — фундаментальні досліди, які прямо не лягають у ці три.
- Головні параметри умов: частка кисню (% об.), тиск, швидкість і напрям потоку,
  тип і геометрія палива, гравітація.
- Ключовий сценарій челенджу: бази й ровери з ≥30% O₂ і тиском ≤10.2 psi (≤70.3 кПа).
  Скафандр: 100% O₂ при 4.3 psi (29.6 кПа). Земля: ~21% O₂, 14.7 psi (101.3 кПа).
- Даних про часткову гравітацію в PSI немає. E-FIELD Flames її імітує електричним полем.
- Перерахунок: 1 psi = 6.894757 кПа, 1 atm = 101.325 кПа, 1 mmHg = 0.133322 кПа,
  1 bar = 100 кПа, мольна частка × 100 = % об.

## 8. Чого не робити

- Не робити власних фізичних висновків і не «покращувати» висновки авторів.
- Не будувати модель горіння без підтвердження від предметника, що колонки означають те, що ми думаємо.
- Не писати ракетну тематику й паливо для двигунів: це поза межами челенджу.
- Не комітити ключі, файли понад 50 МБ і папку `.cache/`.
- Не переписувати чужий код «заодно».
