# Архітектура

## 1. Потік даних

```
psi.nasa.gov ──ingest──► data/raw/PSI-xx/        метадані досліджень, 22 CSV, малі ReadMe
                              │
     normalize ◄── маппінги ──┤──► data/processed/tests.json
     cards ◄── метадані ──────┤──► data/processed/investigations.json
     build ───────────────────┤──► data/processed/scenarios.json, meta.json
                              │
                  contracts/validate.py          перевірка формату
                              │
                apps/web                         статичний сайт; усе рахується в браузері
                              │
                     GitHub Pages                публічне посилання
```

Дві частини, дві команди, одна межа:

- **Пайплайн (Python, pandas)** запускається локально й пише чотири JSON-файли в `data/processed`.
- **Сайт (Next.js, TypeScript)** читає ці файли під час збірки й рахує все в браузері.
- **Контракт** у `contracts/` описує формат файлів. Зразки в `data/fixtures` дозволяють сайту
  будуватись до появи справжніх даних.

База даних не потрібна: 24 картки і 2 870 рядків таблиць, які ніхто не змінює.

## 2. Де працює AI

**LLM працює наперед, а не під час роботи сайту.** Кожен його результат лежить файлом у репозиторії
і проходить перевірку кодом. План і подробиці: `docs/14-si-integration-plan.md`.

| Робота LLM | Що робить код і людина |
|---|---|
| пропонує маппінг таблиці: колонка → поле контракту, одиниця, перетворення | код застосовує маппінг до всіх рядків; скрипт звіряє значення з клітинками |
| знаходить умови тесту в інших файлах дослідження й пише правило поєднання | значення переносить код; поле позначене в `inferred`, клітинка процитована в `notes` |
| читає нотатки оператора BASS: займання, наслідок, час горіння (`pipeline/mappings/si/`) | код приймає значення лише з дослівною цитатою з клітинки; відкинуте йде в журнал |
| пише SI brief для п'яти готових сценаріїв з фактів, які порахував сайт (`apps/web/src/content/briefs.json`) | код звіряє кожне число й назву в тесті й у браузері; речення без перевірки не показується |

Тексти карток модель не пише: це дослівні речення метаданих PSI, які перевіряє код.
Працювати можна через AI-агента для коду або через API. Використання записуємо в `docs/si-usage-log.md`.

**Пізніше: живий brief для власних значень середовища.** Потребує серверної функції для ключа,
тому хостинг доведеться змінити.

## 3. Чому так

- **Сайт має працювати тижнями.** Переможців оголошують 26 січня 2027 року. Статичний сайт не залежить
  від балансу, лімітів і чужих серверів.
- **Без бази даних.** Фільтр по 2 870 рядках у браузері швидший за мережевий запит, а безплатні бази
  засинають або видаляються задовго до кінця оцінювання.
- **Маппінг на таблицю, а не AI на рядок.** 22 маппінги замість тисяч рядків: результат відтворюваний,
  помилку видно в одному файлі.
- **Детерміноване ранжування.** Науковець має бачити, з чого складається бал.
- **Python для даних, TypeScript для сайту.** Кожна команда працює своєю мовою, а межа між ними — JSON.

## 4. Структура репозиторію

```
flame-atlas/
  AGENTS.md  CLAUDE.md  README.md
  contracts/               контракт даних: схеми, типи, перевірка
  docs/                    документи команди
  tracks/                  списки задач двох команд
  pipeline/                Python: ingest, normalize, cards, build
    mappings/              маппінги таблиць і словник матеріалів (JSON)
  data/
    raw/                   з PSI: метадані й CSV у git
    processed/             чотири файли для сайту (в git)
    fixtures/              зразки в тому самому форматі
    review/                ручна перевірка: вибірки, сценарії, знахідка
  apps/web/                Next.js: сторінки, компоненти, логіка
  submission/              тексти подання, слайди, джерела
```

## 5. Формула ранжування (v0)

Бал дослідження для сценарію: `score = 100 × Σ wᵢ · sᵢ`.

| Складник | Як рахуємо | Вага |
|---|---|---|
| `o2` | 1, якщо кисень сценарію в діапазоні тестів дослідження; інакше `exp(−(d/8)²)`, де d — відстань у відсоткових пунктах | 0.25 |
| `fuel` | 1, якщо стан палива збігається; 0.5 для визнаного аналога (газовий пальник BRE імітує тверді матеріали); 0 інакше | 0.20 |
| `pressure` | як `o2`, з масштабом 25 кПа | 0.15 |
| `pillar` | 1 для основного напряму; 0.6 для додаткового; 0.2 інакше; 1, якщо фокус `all` | 0.15 |
| `flow` | як `o2`, з масштабом 15 см/с | 0.10 |
| `data` | обсяг даних: логарифм кількості рядків, наявність таблиці, кількість статей | 0.10 |
| `gravity` | для 0 g: micro = 1; для Місяця й Марса: partial-simulated = 0.9, micro = 0.7, normal = 0.5 | 0.05 |

Якщо значення `null`, складник дорівнює 0 (немає даних — немає балів) і з'являється застереження; картка пише, скільки зі 100 балів вдалося перевірити за даними.
Ваги лежать у конфігу сайту. Їх калібруємо на трьох демо-сценаріях і записуємо в `docs/decisions.md`.

Уточнення, зроблені під час реалізації (`apps/web/src/domain/rank.ts`, усі числа в `apps/web/src/domain/config.ts`):

- **`flow`.** Порівнюємо два діапазони: 1, якщо вони перетинаються, інакше `exp(−(d/15)²)` від проміжку між ними.
  Середовище без примусового потоку порівнюємо з 0 см/с.
- **`fuel`.** Аналог приходить з даних: поле `fuelAnalogOf` у картці дослідження (контракт 1.1.0) зі станами палива
  й твердженням з джерелом. У зразках це PSI-20 (ACME BRE), газовий пальник, який імітує тверді й рідкі палива. Якщо в середовищі не вибрано жодного стану палива, складник дорівнює 1.
- **`data`.** `0.6 × min(1, log₁₀(1 + рядки) / log₁₀(1 + 300)) + 0.2 × (є таблиця) + 0.2 × min(1, статті / 5)`.
- **`gravity`.** Середовище ділимо на класи: до 0.01 g — мікрогравітація, від 0.9 g — земна, між ними — часткова.
  Для мікрогравітації й земної: той самий рівень 1, імітована часткова 0.7, протилежний 0.5.
  З кількох рівнів гравітації дослідження беремо найкращий.
- **Бал** округлюємо до одного знака. Однакові бали впорядковуємо за номером дослідження.
- **Найближчі рядки.** Відстань від середовища до рядка рахує `conditionDistance`: кисень, тиск і потік
  у своїх масштабах, з тими самими вагами, що й у балі. Умова, якої рядок не повідомляє, рахується як відстань,
  що дає 0.5: так рядок із пропуском не стає ні кращим, ні гіршим за інші рядки того самого дослідження. Спершу беремо окремі тести; зведені рядки лише тоді, коли тестів у дослідженні немає.
- Бал означає близькість умов, а не оцінку безпеки. Це написано на екрані.

## 6. Деплой

Деплой правилами хакатону не вимагається: достатньо публічного репозиторію. Робимо його, бо статичний
сайт розгортається безплатно, а живе посилання показує журі завершений продукт.

- **GitHub Pages** з цього ж репозиторію. GitHub Actions збирає сайт і публікує його на кожен пуш у `main`.
- Адреса: `https://vlo0d.github.io/flame-atlas/`. У `next.config` потрібні `output: 'export'`,
  `basePath: '/flame-atlas'`, `images.unoptimized: true`, `trailingSlash: true`.
- Сторінки досліджень генеруються наперед для всіх 24 id.
- Секретів немає.
- Страховка: README зі знімками екрана й слайди показують продукт, навіть якщо сайт недоступний.

## 7. Ризики

| Ризик | Що робимо |
|---|---|
| AI вигадує числа чи висновки | цитати перевіряє код; ручна вибірка; `null` замість здогаду |
| Маппінг таблиці неправильний | інша людина звіряє 5 рядків з CSV; маппінг — це JSON, який виправляється вручну |
| Колонку таблиці витлумачено неправильно | перед маппінгом читаємо ReadMe дослідження: там пояснено кожну колонку (задача DA-9) |
| У таблицях BASS і BASS-II немає наслідку тесту | перевірено: у малих файлах PSI його теж немає; показуємо «not reported» і пишемо про це в обмеженнях |
| Рядки таблиць видають за тести | поле `granularity`; сайт рахує тести лише за рядками `test` |
| Не встигаємо всі 22 таблиці | порядок у задачі DA-10; решта досліджень лишається з картками без рядків |
| Формат даних розходиться між командами | контракт у `contracts/`, перевірка в CI, зразки тієї самої форми |
| Сайт недоступний під час оцінювання | статичний хостинг; README зі знімками екрана й слайди як страховка |
