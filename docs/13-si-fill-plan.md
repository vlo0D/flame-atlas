## 2. Головне правило

SI **знаходить і переносить** значення, яке вже є в іншому файлі NASA, або **пропонує метод**, за яким
**код рахує** значення з рядів даних NASA. SI **не вигадує** значень, яких ніхто не вимірював.

- Значення з таблиці NASA ніколи не перезаписуємо. Якщо джерело з ним не згодне — це `conflict`, не заповнення.
- Немає джерела — поле лишається `null`.
- Прогноз моделі — не дані. У `tests.json` він не потрапляє.

## 4. Три види пропусків

| Вид | Що робимо | Хто робить | Приклад |
|---|---|---|---|
| **1. Перенесення** (`transfer`) | значення є в іншому файлі NASA | Claude пише правило відповідності; код переносить і перевіряє, що число є в джерелі | BASS: `As Run_Test Matrix.xlsx`; FLEX: `TestSheet.txt` |
| **2. Розрахунок** (`derived`) | значення випливає з рядів даних | Claude пропонує метод; рахує детермінований код | FLEX/CFI: час горіння й діаметр згасання з `DropletData.txt` |
| **3а. Не застосовно** | поле не має сенсу для цього типу тесту | правило в коді | швидкість поширення для крапель і газу; товщина зразка для газу |
| **3б. Не вимірювали** | значення ніде немає | лишається `null` | наслідок тестів BASS-II, якщо його немає й у звіті |

Окремий підвид першого: **SI-класифікація тексту** (`si-text`). Колонка спостережень у матриці BASS
(«Test Observations and Anomalies») — вільний текст. Claude визначає з нього `ignited` і `outcome`
і повертає **дослівну цитату**. Код приймає відповідь, лише якщо цитата є в клітинці дослівно.

### `TestRecord`: два нові необов'язкові поля

```ts
fills?: Fill[];            // заповнені SI значення, по одному на поле
notApplicable?: string[];  // поля, які не мають сенсу для цього тесту: ["spreadRateMmS", "thicknessMm"]

type Fill = {
  field: string;                       // шлях поля: "o2PctMin"
  value: number | string | boolean | number[];
  method: "transfer" | "derived" | "si-text";
  source: {
    investigationId: string;           // "PSI-26"
    fileName: string;                  // назва файла в PSI, як в інвентарі
    locator: string;                   // "as run matrix!AA4", "line 12", "DropletDiameter_mm, rows 1-412"
    rawText: string | null;            // вміст клітинки або рядка дослівно: "0.221"
  };
  quote: string | null;                // для si-text і документів: дослівна цитата
  derivation: string | null;           // для derived і перетворень: "fraction × 100", "mean over burn"
  check: { status: "verified" | "rejected" | "conflict"; rule: string };
  by: { kind: "rule" | "llm"; model: string | null; promptVersion: string | null; mappingVersion: string };
};
```

- Основне поле (`o2PctMin` тощо) отримує значення, а його шлях додається в чинне поле `inferred`.
  Так сайт, який ще не знає про `fills`, покаже значення і не зламається.
- `raw` не змінюється: вихідний рядок таблиці лишається як був.
- У `tests.json` потрапляють лише `verified`. `rejected` і `conflict` пишуться в `data/review/si-fill-log.csv`.

### Перевірки коду (кожне заповнення)
1. `rawText` справді є у файлі за `locator` (перечитати файл і порівняти).
2. Перетворення одиниць — лише за таблицею з `contracts/README.md`.
3. Діапазон правдоподібності: O₂ 0–100%, тиск 0–500 кПа, потік 0–100 см/с; інакше `rejected`.
4. Поле в таблиці NASA не `null` → не заповнюємо; якщо джерело не згодне більше ніж на 1% → `conflict`.
5. `si-text`: цитата є в клітинці дослівно; значення відповідає переліку контракту.
6. `derived`: перехресна перевірка з наявною колонкою, де вона є (FLEX: `K` ↔ `Burning rate`).

### Claude у пайплайні
- **Правила відповідності й методи** пише агент (Claude Code) у `pipeline/mappings/fill/*.json`,
  подивившись 5–10 зразків файла і словник колонок. Людина читає правило перед запуском.
- **`si-text`** — вільний текст: спостереження в матрицях BASS і BASS-II, `Comments.txt` ACME,
  описи в документах. Виклик Claude API під час збірки, не на сайті:
  - модель `claude-opus-5-5`, структурований вихід (`output_config.format` або `client.messages.parse()`),
    `effort: "low"` для класифікації; перевіряти `stop_reason` (у т. ч. `refusal`) перед читанням відповіді;
  - схема відповіді: `{ ignited: true|false|null, outcome: <enum контракту>|null, quote: string|null }`;
    `null`, якщо в тексті немає відповіді — модель не здогадується;
  - тисячі коротких текстів — пакетом (Message Batches), не по одному запиту;
  - результат кешувати в `pipeline/mappings/fill/<дослідження>-text.json` разом із моделлю й версією промпту,
    щоб перезбірка не викликала API вдруге і була відтворюваною;
  - перед кодом агент завантажує skill `claude-api` (там актуальні виклики SDK);
  - облікові дані: якщо `ANTHROPIC_API_KEY` немає, перевірити `ant auth status`, потім спитати користувача.

Сайт статичний; усе береться з `fills` у `tests.json` і `siFill` у `meta.json`. Кольори — лише з токенів

Клік або фокус відкриває панель: метод (`Transferred from` / `Computed from` / `Read by SI from text`), файл і місце (`As Run_Test Matrix.xlsx · as run matrix!AA4`), вихідний текст (`0.221`), перетворення (`fraction × 100 → 22.1 %`), цитата, статус перевірки, модель для `si-text`, посилання на дослідження в PSI | `src/features/tests/tests-view.tsx` |
